# Visual Rules

## Style Menu

- `editorial`: literary classics, essays, philosophy, cognition.
- `ink-sketch`: serious literature, psychological scenes.
- `franco-belgian-bd`: clear premium storytelling.
- `manga`: high emotion and dramatic plot.
- `webtoon-manhwa`: mobile-first vertical reading.
- `manhua`: Chinese social platform storytelling.
- `comic-strip`: satire and short punchlines.
- `doodle`: light knowledge and warm study notes.
- `retro-halftone`: punchy retro framing.

## Character Bible Levels

- One-shot: fingerprint plus approved reference.
- Short series: reference plus recurring prop and costume lock.
- Long novel/literary series: turnaround, expressions, recurring costumes, relationship map, environment anchors.

## Visual Identity Lock

- Style reuse is not design reuse. `style_id` controls line, color, medium, lettering mood, and comic grammar only; it must not carry over characters, relationship structures, era, geography, environments, props, motifs, or opening compositions.
- Every formal project must create `planning/visual_identity.json` before image prompts. Required systems: `book_signature`, `adaptation_form`, `cast_model`, `character_system`, `environment_system`, `motif_system`, `palette_lighting`, `camera_composition`, and `forbidden_carryover`.
- `extract` and `init-project` may only create `needs_host_planning` empty schemas. They must not inject a hidden default reader/mentor pair, study, glowing doorway, empty chair, stack of books, or any reusable plot template.
- Historical, political, and institutional books should usually use ensemble/group/institutional role structures, not a modern reader plus mentor. Practical/cognitive books may use modern roles only when the role, setting, prop, and conflict are custom to the book. Literary books should preserve period, atmosphere, and relationship texture rather than force modern jokes.
- Run `validate-visual-identity` and `validate-distinctiveness` before `build-visual-contract`. Distinctiveness is local JSON-only; no API or embeddings. `<0.55` passes, `0.55-0.70` warns, `>0.70` fails, and role relationship + environment + props/opening collisions fail directly.
- Every formal prompt must include `Project visual identity lock` with book-specific adaptation form, cast model, character shape language, era/geography, environment language, signature motifs, palette/lighting, camera/composition, and forbidden carry-over.
- `visual_contract.json` stores `visual_identity_sha256`. If `visual_identity.json` changes, `validate-visual-contract` must fail until the visual contract and reference pack are rebuilt.

## Image Text

Do not ask image models to render Chinese text, numbers, signs, labels, UI, prices, or equations. Add text in post-production.

## Vector Fallback

The vector backend must produce real readable panel art with people, settings, props, camera variation, and continuity. It must not emit blank cards, placeholders, solid-color frames, or “pending generation” images.

Vector is `draft-fallback`, not high-quality final art. If the user asks for production-grade artwork, New Yorker-style editorial panels, or “like the Faust output”, use host-image or local-model. If neither exists, stop and report that the high-quality image backend is unavailable instead of shipping vector as final.

## Host Image Handoff

Host-image artwork is generated by the current Codex/Claude image tool, not by Python. The host must:

1. Generate or reuse an approved character reference.
2. Run `book-to-comic doctor-image-backends <project> --selftest-image` when diagnosing final-art platform support.
3. The default final-art path is the Artifact Materializer loop (visual contract -> host image tool -> materialize -> approve). `book-to-comic generate-final <project>` / `scripts/generate_final.py` are LEGACY worker-compat paths kept for diagnosis only.
4. Generate each panel as image-only art with no readable text.
5. Save or recover accepted PNG/JPEG/WebP files into `host-image-output/EPxx/`.
6. Import, compose, and export only after per-panel host QA approves each asset (bulk imports are tiered `imported`, never `high`).

When the active Codex/Claude session exposes a built-in image generation tool, the agent should execute the generated jobs itself: call the image tool once per panel, copy or move the saved asset into the required `host-image-output/EPxx/NN.png` path, then run import/compose/export. Do not ask the user to screenshot, drag, or copy files.

Do not assume that all Codex or Claude surfaces have the same image tool. Treat built-in image generation as a host-session capability: Codex Desktop may expose `image_gen`, while Codex CLI or other surfaces may not; Claude visual understanding, Artifacts, file creation, or data visualization do not by themselves prove comic-grade image generation. Always require saved-PNG self-test.

High-quality mode requires a live saved PNG round-trip. If the host only displays preview images, can only launch a CLI without passing image self-test, or cannot expose files, treat host-image as unavailable, write/read `image-backend-report.json`, and do not ship vector as high-quality final art. Do not ask the user to manually screenshot, drag, or copy preview images into the project.

## Lettering

Use style-matched post-production lettering. Editorial mode uses serif type, open captions, restrained borders, paper texture, and whitespace. Avoid a hard pasted subtitle band.
